# Email run — extra rules (Roni)

The "📬 Email run" routine reads this file every run. These rules add to / override its prompt.

1. **Summary leads with the key fact.** First words = the single most important thing: amount, due date, deadline, or who needs what. ≤ 25 words (money alerts up to ~60).
2. **Balances on money alerts.** Citi, Amex, Chase, Apple Card, any bank/card/lender alert: read the body and include the current balance / statement balance / available credit and minimum payment + due date whenever the email shows them. Format: "… · Balance $X · Avail $Y · Min $Z due Nov 4".
3. **COVE reports get a highlight.** Any COVE report (sales, traffic, leads, marketing, broker, weekly/daily reports — Cove Miami/Edgewater, Elliman, M18 PR): read the body and start the Summary with "★ " + the one standout fact, ending with " · " — e.g. "★ 2 new contracts (#1204, #905), $3.1M · 14 showings, 38 leads". Pick what changed or matters most: contracts/sales, price changes, big drops or jumps, problems.
4. **Chase alerts: summarize every transaction.** Every Chase email (alerts, wires, ACH, Zelle, debit/credit card, ATM, balance): read the full body of every message and put each transaction in the Summary as "Payee $amount (xLAST4, date)" joined by " · ", then the balance if shown. Never write "Chase alert", "transaction notice" or "large purchase approved" without the payee and amount. Chase "secure message" emails have no details — say so and give the title.
5. **Catch-up: nothing stays unsorted.** In every Scan (STEP 4), after the normal "newer_than:1d" + starred search, ALSO search "in:inbox -is:starred older_than:1d" (page through) and sort every thread that has no EmailRun row yet, newest first, up to 100 per run. Same rules as any other thread. Put "catch-up N" in the request Detail.
6. **Dollar value on invoices, proposals, bids, quotes, change orders, requisitions, estimates, contracts, POs, statements, payment requests.** Read the body (and the attachment name/preview if the amount is only there) and put the total in the Summary: "{Vendor} invoice #123 $4,250.00 due Nov 15" / "{Sub} bid $185,000 for {scope}". Several items → list each with its amount. If no amount can be found, say "amount not in email" — never leave it out silently.
7. **To-do notes are instructions.** Every run, read Airtable EmailNotes tblNotes = tbl90HorcK1relti7 (ThreadId fldDXHJjnQ0I2kLni, SnoozeUntil fld5y3ev6bAFS0rwH = set by the page, leave it alone, Note fldmCBP70vdtQ89ch, Subject fldzBbEzCemQ8rHVl, From fldrbZXiO2dOMRaQI, Result fldqmOhrk3ehG3m8v). For each row with Note set and Result empty, treat Note like an EmailRun Answer (STEP 3) for that ThreadId:
   - a reply ("reply …", "tell him …", "say yes …") → write the Draft on that thread's EmailRun row (Bucket D, Status New) for Roni to approve — never send it yourself;
   - a forward or a message to someone who is not on the thread ("forward to …", "send to …", "email Leora …", "ask Michelle to …") → follow rule 10;
   - a task ("task …", "remind me …", "follow up …") → create an Items row (Task "Email: {Subject} — {note}", Status Open, Source "Claude", TextExclude true);
   - anything else you can do without sending or spending → do it.
   Then write Result = "✓ {what you did, ≤ 15 words}" (or "? {one short question}" if unclear). If Roni edits the Note later he clears Result, and it's handled again.
8. **Auto-replies → Archive.** Out-of-office / automatic replies (subject like "Automatic reply", "Auto-Reply", "Out of Office", or header Auto-Submitted: auto-replied) always get Bucket "A · Archive", Summary = "Auto-reply from {name}" + return date if given.
9. **Summarize the newest message.** Summary (and Advice) describe the LATEST message in the thread (who wrote last, what it says/asks), using earlier messages only as context. If a thread already in EmailRun got new messages since its row was written, rewrite that row's Summary/Advice/Bucket for the newest message.

   - Writing one: when a note or Answer says to forward, or to tell someone who is not on the thread, put their addresses in ForwardTo and the short note to them in Draft (Bucket D, Status New). 11. **American Express: payee and amount, always.** Every American Express or Amex email (charges, large purchase alerts, payments, statements, fraud alerts): read the full body and put each transaction in the Summary as "Payee $amount (xLAST4, date)" joined by " · ", then the balance if shown. Never write "Amex alert" or "large purchase" without payee and amount. If the email really has neither, say "payee and amount not in email". Amex alerts are never fast-path A: read them first.
12. **Daily reports get a highlight.** Any email with "daily report" in the subject, from any project: read the body (and the attachment name or preview if the report is only there) and start the Summary with "★ " + the one standout fact, ending with " · ", as in rule 3. Pick what changed or matters most: work done, manpower, delays, problems, inspections, deliveries. Never write only "Daily report received". Daily reports are never fast-path A: read them first.
13. **Fix old rows for rules 11 and 12.** Every run, find EmailRun rows with Status New from American Express or with "daily report" in the Subject whose Summary breaks those rules, and rewrite them, up to 25 per run.
